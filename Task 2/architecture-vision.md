## **6. Architecture Vision: Africa Delivery MVP**

**Версия:** 1.0
**Дата:** 05.10.2026
**Автор:** Solution Architect

## **1. Бизнес-контекст**

Запуск маркетплейса Africa Delivery в Нигерии и Кении. Цель — стать «Amazon для Африки» с фокусом на низкие цены, мобильные платежи (M-Pesa, Flutterwave) и доставку через локальных партнёров. Ключевые особенности: 100% мобильный трафик (3G/LTE), офлайн-аудитория (USSD/SMS), локализация данных (NDPR, POPIA, KICA).

## **2. Цели**

### **Цели (на 15.10.2026)**

1. Запустить PWA и нативные приложения (iOS/Android) с каталогом на 5000 SKU.
2. Подключить 100 продавцов через простой онбординг (менеджер + WhatsApp).
3. Обеспечить оплату через M-Pesa (Кения) и Flutterwave (Нигерия).
4. Интегрировать доставку через Sendbox (Нигерия) и Sendy (Кения).
5. Уведомления: SMS + WhatsApp Business API.
6. Дашборд для CEO (регистрации, заказы, выручка — обновление раз в минуту).

### **Осознанно отложены:**

1. **Микросервисная архитектура** — монолит до достижения 100k DAU.
2. **Собственная логистика** — интеграция с Sendbox/Sendy до момента, пока объём заказов не оправдает собственный флот.
3. **Собственный платёжный шлюз** — используем API M-Pesa/Flutterwave.
4. **Live-стримы** — запуск через 2–3 недели после MVP.
5. **Блокчейн-лояльность** — бэклог, оценка после запуска.
6. **B2B-сегмент** — через 12 месяцев.
7. **Сельские районы (USSD/SMS)** — базовый сценарий «проверить статус заказа», полноценный заказ — через 2 месяца.

## **3. Архитектурные принципы**

| **Принцип** | **Описание** |
| --- | --- |
| **1. Late Binding** | Не делаем дорогих решений до появления реальных данных о нагрузке. |
| **2. Простота превыше всего** | Меньше движущихся частей — меньше шансов на отказ. |
| **3. Партнёрские API** | Используем лучшие локальные сервисы, а не строим своё. |
| **4. Локализация данных** | Данные остаются в стране (Нигерия, Кения). |
| **5. Мобильность-first** | PWA + адаптивность под 3G/LTE, кеширование контента. |
| **6. Наблюдаемость** | OpenTelemetry + Grafana + Prometheus с первого дня. |

## **4. Ключевые архитектурные решения**

| **Решение** | **Обоснование** |
| --- | --- |
| **Модульный монолит на Go** | Быстрее всего до MVP, дешевле в эксплуатации, легко масштабируется до 100k DAU. |
| **PostgreSQL как основная БД** | Надёжность, поддержка JSONB, лицензия Open Source. |
| **Redis для кеша и очередей** | Кэш каталога, сессии, корзины; Redis Streams для фоновых задач. |
| **Kubernetes (K3s) для оркестрации** | Соответствие CNCF, портируемость между провайдерами, GitOps-подход. |
| **Интеграция через REST API партнёров** | M-Pesa, Flutterwave, Sendbox, Sendy, WhatsApp, SMS — внешние системы. |

## **6. Масштабирование (Roadmap)**

| **Фаза** | **Время** | **Масштаб** | **Действия** |
| --- | --- | --- | --- |
| MVP | 15.10 | 5k SKU, 100 продавцов, 2 страны | Монолит, 2 VPS, партнёрские API |
| Рост | 6 мес. | 50k DAU | Выделение модулей (платежи, логистика) в сервисы, CDN |
| Экспансия | 12 мес. | 200k DAU, 5 стран | Полноценные микросервисы, мульти-регион, Kafka |
| Масштаб | 3 года | 10M+ DAU, 15 стран | Полный Cloud Native (CNCF), active-active |

## **7. Риски и митигация**

| **Риск** | **Митигация** |
| --- | --- |
| Срыв дедлайна | MVP-скоуп, 6 недель на разработку, партнёрские API |
| CTO не согласен | ADR №1 с TCO-расчётом, пилотный вывод модуля через 3 мес. |
| Юридические требования | Консервативная локализация, consent-manager, аудит через 6 недель |
| Провайдеры недоступны (M-Pesa/Sendbox) | Резервные API (Paystack, Sendy) в коде, не в конфигурации |
| Недостаточный спрос | Метрики с первого дня: регистрации, конверсия, повторные заказы |
