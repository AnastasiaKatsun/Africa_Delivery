## **5. ADR №4: Выбор платёжного провайдера**

# **ADR №4: Выбор платёжного провайдера**

**Статус:** Принят
**Дата:** 07.10.2026
**Автор:** Solution Architect (Анастасия Кацун)

### **Контекст**

Платёжные операции — критический компонент. Инвестор требует запуск 15.10, CFO — комиссию ≤ 2,5% от GMV. CTO предлагает собственную платёжную оркестрацию (build-not-buy). Необходимо выбрать провайдера и способ интеграции.

### **Решение**

Используем **прямые партнёрские интеграции** с локальными платёжными провайдерами:

| **Страна** | **Основной провайдер** | **Резервный провайдер** | **Комиссия** |
| --- | --- | --- | --- |
| Нигерия | **Flutterwave** | Paystack | 1,5% + $0,20 / транзакция |
| Кения | **M-Pesa (Daraja API)** | Flutterwave | 1,8% + $0,10 (M-Pesa) |
| ЮАР | **Paystack** | Flutterwave | 2,0% + $0,20 |

Прямые интеграции вместо общего платёжного шлюза (типа Stripe).

### **Обоснование**

| **Критерий** | **Прямые API (Flutterwave/M-Pesa)** | **Агрегатор (Stripe)** | **Собственная разработка** |
| --- | --- | --- | --- |
| Комиссия | **1,5–2,0%** | 2,9% + $0,30 | 0% (но $120k разработка) |
| Время до MVP | **2–3 недели** | 1–2 недели | 6+ месяцев |
| Сложность | Средняя (разные API) | Низкая (единый API) | Высокая |
| Регуляторика | Уже есть лицензии | Требует партнёрства | Лицензия невозможна за 2 мес |
| География | Локальные провайдеры знают рынок | Не оптимизированы под Африку | — |

### **Отвергнутые альтернативы**

1. **Stripe / агрегатор:** комиссия 2,9% + $0,30 — превышает лимит CFO (2,5%). Для GMV $15M/год это разница в $120k.
2. **Собственная платёжная оркестрация (CTO):** $120k разработки + 6 месяцев. Нереалистично для запуска 15.10.
3. **Токенизация через одного провайдера:** создаёт единую точку отказа.

### **Последствия**

**Позитивные:**

* Комиссия 1,5–2,0% ≤ 2,5% — укладываемся в требование CFO.
* Прямые интеграции дают гибкость (переключение провайдера при необходимости).
* Соответствие локальным регуляторам (лицензии есть у провайдеров).

**Негативные:**

* **Техническая сложность:** три разных API, разные форматы, разные процедуры возвратов.
* **Регуляторные риски Кении:** данные, связанные с платежами (KICA), требуют строгой локализации — мы должны использовать локальных провайдеров.

### **Риски и митигация**

* **Риск:** M-Pesa недоступна → **Митигация:** переключение на Flutterwave (Circuit Breaker).
* **Риск:** Flutterwave повышает комиссию → **Митигация:** контракт с фиксацией комиссии на 12 мес.
* **Риск:** Несоответствие требованиям CBN (Нигерия) → **Митигация:** юр. аудит после получения заключения.
